================================================================================
 1. WHAT THIS APP IS
================================================================================

A fully offline Android viewer for an Instagram "Download your information" DM
export (the JSON flavour, not HTML).

Input:  a .zip of the export, or an already-unzipped folder.
Output: a local chat list, per-chat message timeline, media playback, search,
        notes, per-contact renames/photos, themes. Nothing leaves the device.

The app is NOT:
  - a sync client (no network permission at all, no INTERNET in the manifest)
  - an editor of the export (the export folder is read-only, always)
  - a replacement for the desktop Tauri app (separate codebase, separate build)
  - backed by the Rust core (no JNI, no UniFFI, no `core/` module)

Everything below the UI is a hand-written Kotlin port of the desktop Rust core's
documented rules: scan layout, dedupe key, display order, text repair, media
containment, MIME allowlist.


================================================================================
 2. NON-NEGOTIABLE RULES
================================================================================

These come from the repository's AGENTS.md but are phrased for Android. Breaking
one of these is a bug even if the feature "works".

2.1 Offline, always
    - No INTERNET / ACCESS_NETWORK_STATE permission. Do not add one.
    - No analytics, crash reporting, auto-update, remote config, CDN fonts or
      images. Everything is bundled in res/ or drawn with Compose.
    - Any new dependency must work with networking disabled and must not phone
      home at runtime.
    - Verify: `grep -i internet android-app/app/src/main/AndroidManifest.xml`
      must stay empty.

2.2 The export folder is read-only
    - Never write, rename, delete or create anything inside a picked export.
    - All app writes go to app-private storage (filesDir / cacheDir) or to a
      folder the user explicitly picked with the system picker (downloads).
    - Media is opened read-only; downloads use a SAF tree URI, never the export.

2.3 Every path/URI inside the JSON is untrusted
    - Media URIs are resolved by MediaResolver only. It rejects `..`, absolute
      paths, symlinked components and anything that escapes the root, and it
      verifies the canonical path afterwards.
    - Never build a File from a JSON string anywhere else.
    - Never trust `thread key` / folder names as path segments blindly; the
      existing code treats them as a single name under the inbox directory.

2.4 Chat text is untrusted content
    - Compose `Text(...)` is safe by default (no HTML parsing). Keep it that way.
    - Never use AndroidView/WebView or Html.fromHtml to render message content.
    - Links: LinkText() only makes http/https clickable. Do not make other
      schemes clickable (no intent:, file:, content:, javascript:).
    - Search highlighting uses buildAnnotatedString with explicit ranges; it
      never re-parses the text as markup.

2.5 No real chat data in the repository or in tests
    - Tests use generated data only.
    - Never copy a real export into the repo, a fixture, a screenshot or a log.
    - Do not log message text, sender names or export paths. The app installs no
      logger; keep it that way.

2.6 Minimal, explained permissions
    Current manifest permissions:
      - MANAGE_EXTERNAL_STORAGE   (Android 11+): lets the app read the chosen
        export in place instead of copying ~2 GB. Optional; user grants it in
        system Settings. If denied, the app copies into app storage instead.
      - READ_EXTERNAL_STORAGE (maxSdkVersion 29): the pre-Android-11 equivalent.
      - ACCESS_NETWORK_STATE: NOT declared here. media3-common (ExoPlayer) merges
        it in through its own manifest. It only lets a library read connectivity
        state; it grants no network access, and there is still no INTERNET
        permission. Removing it would mean overriding a dependency's manifest,
        which was not done because local playback could not be device-tested.
      - com.igviewer.archive.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION: generated
        by AGP for targetSdk 34+ as a self-scoped signature permission.
    No other permission. If you add one, justify it in this file and in the
    manifest comment, and prefer a SAF picker over a broad permission.
    The check that matters is INTERNET:
      grep -i internet android-app/app/src/main/AndroidManifest.xml   # must stay empty

2.7 Explain every new dependency
    Current runtime deps: core-ktx, lifecycle-runtime-ktx, activity-compose,
    Compose BOM (ui, tooling, material3), media3-exoplayer.
    Test deps: junit4, org.json (the real implementation, so ingest/JSON tests
    run on the JVM instead of hitting Android's throwing stub).

4.5 Changing serialized models (read before editing Models.kt)
    ArchiveIndex snapshots use Java serialization.
    - `Persisted` declares serialVersionUID = 1L, so its shape can grow and
      missing fields read back as null/defaults.
    - `KeptMessage`, `MediaRef` and `ThreadSummary` do NOT declare
      serialVersionUID. Adding, removing or retyping a field changes the
      computed UID, so existing per-thread snapshot files fail to deserialize.
      ArchiveIndex.loadThread swallows the exception and returns null, which
      becomes an EMPTY message list: the chat still appears in the list but
      opens blank.
    Consequence: after changing those classes, do not trust an old snapshot.
    Either:
      - add an explicit `serialVersionUID = 1L` to the class first and keep new
        fields default-tolerant (missing fields then read back as null/0), or
      - invalidate the snapshot so the app rebuilds from the saved roots
        (Delete imported data, or introduce a schema marker), and re-import.
    Test the upgrade path with an old snapshot before shipping.

 6. DATA LAYER REFERENCE
================================================================================

6.1 Models.kt
    MediaRef(kind, mediaIndex, uri)            Serializable
      kind is one of: photos, videos, audio_files, gifs, sticker, files
      uri is RAW, exactly as in the JSON (never Text.fix'ed)

    KeptMessage(seq, fileNo, idxInFile, tsMs, sender, content, isUnsent,
                callDuration, media, reactions, share)   Serializable
      seq        per-thread RAW encounter counter BEFORE dedupe
      sender     already Text.fix'ed
      content    already Text.fix'ed, nullable
      reactions  List<Pair<actorFixed, reactionFixed>>
      share      (raw link, fixed share_text), nullable, NOT in the dedupe key

    ThreadSummary(key, title, participants, keptCount, rawCount,
                  firstTsMs, lastTsMs, lastPreview)      Serializable
      lastPreview is precomputed so the chat list never loads messages.

    ThreadIngest(title, participants, kept, rawCount)
    SkipReason enum with stable codes: not-a-message-file, file-number-overflow,
      duplicate-file-number, symlink, too-large, io-error, invalid-utf8,
      malformed-json, invalid-schema, thread-unreadable
    ThreadScan(key, files, skipped)
    ScanResult(threads, skipped)

6.2 Scanner.kt  (port of the Rust `scan` module)
    - Inbox discovery is bounded to at most two wrapper levels:
        <root>/your_instagram_activity/messages/inbox
        <root>/messages/inbox
        <root>/<w1>/your_instagram_activity/messages/inbox
        <root>/<w1>/<w2>/your_instagram_activity/messages/inbox
      If none exists, a bounded depth-5 walk finds directories that directly
      contain message_N.json. It does not descend past a qualifying directory,
      so it never wades through media trees.
    - parseFileNumber accepts exactly `message_<digits>.json`; digits only,
      <= 0xFFFFFFFF (else FileNumberOverflow).
    - Symlinked thread dirs/files are skipped, not followed.
    - Files larger than 32 MiB are skipped (MAX_JSON_BYTES); readBounded never
      buffers past the cap.
    - Duplicate numbers in one thread directory are rejected as a group.
    - Returns files sorted by numeric suffix, ascending.
    - Empty/non-message files are ignored silently, not counted as failures.

6.3 Ingest.kt  (port of the Rust `ingest` module)
    Dedupe key = (tsMs, senderName RAW, content RAW, mediaUris)
      - mediaUris concatenates all six kinds in fixed order:
          photos, videos, audio_files, gifs, sticker, files
        each kind in on-disk order; it is a typed List<String>, never a joined
        string (an `or` chain silently loses kinds).
      - `sticker` is a SINGLE object in Instagram's schema, not an array.
      - Reactions and share are NOT in the key.
      - Values in the key are the RAW strings, before Text.fix.
    Dedupe scope: a message from file N is dropped only if its key already
      appeared in a file with a LOWER number. Identical messages WITHIN one file
      are all kept. First-encountered copy wins.
    Ordering: (tsMs ASC, seq DESC). seq increments for every raw encounter,
      including dropped ones.
    Text.fix is applied to: title, participants, sender, content, reaction actor
      and reaction text, share_text. NOT to share link and NOT to media URIs.

    parseThreadFile reads: title, participants[].name, messages[].
    parseMessage reads: sender_name, timestamp_ms, content, is_unsent,
      call_duration, photos[], videos[], audio_files[], gifs[], sticker{},
      files[], reactions[]{actor, reaction}, share{link, share_text}.
    Any other JSON is ignored. Malformed JSON throws JSONException and is counted
    as a parse failure (the thread keeps going).

6.4 ArchiveIndex.kt
    Construction is private; use:
      ArchiveIndex.index(root, onProgress)
      ArchiveIndex.indexAll(roots, mediaRoots, onProgress)
      ArchiveIndex.loadSnapshot(file)
    Key facts:
      - Multiple roots are merged into ONE archive. If two roots contain the
        same thread key, BOTH get namespaced: "<rootSlug>\u00b7<key>" on both
        sides. A single import keeps its plain keys, so existing per-chat prefs
        (renames, avatars, gallery tab/filter) stay valid.
      - rootByKey remembers which root a thread came from, so media resolves
        against its own export first. This prevents two exports with the same
        relative media path from stealing each other's photos.
      - mediaRoots are extra folders used for MEDIA LOOKUP ONLY; they are never
        scanned for threads, so adding one cannot inject chats.
      - Thread list order: lastTsMs DESC, then title DESC (matches desktop).
      - quickSelf(key): participants contains "me" ? "me" : first participant.
        It reads only the in-memory summary -- never deserialises a thread. Use
        it in list/row code. detectMe(key) loads messages and is for one-off
        explicit detection only.
      - allParticipantNames(): distinct names ranked by thread count DESC, then
        alphabetically. Used by the global "who are you" chooser.
      - mediaFile(uri, threadKey): tries the thread's root first, then every
        root, then mediaRoots; uses per-thread basename maps and caches before
        doing a canonical path resolve. Falls back to basename matching.
      - messages(key): memory cache -> per-thread snapshot file -> empty list.
        @Synchronized.
      - headMessages(key): first 200 from the .head snapshot, or null when the
        thread fits entirely in 200 or no head exists.

    Snapshot format (private class Persisted, serialVersionUID = 1L):
      rootPath, rootPaths?, rootByKeyPaths?, mediaRootPaths?, threads,
      skippedFiles, parseFailures, skipReasons
    Loading is tolerant: unreadable/incompatible snapshots return null and the
    caller rebuilds from the saved roots. Missing newer fields are null-checked.

    saveSnapshot also:
      - deletes and rewrites imports/threads/ (so stale threads never linger)
      - writes <sha256(threadKey)> for each non-empty thread
      - writes <sha256(threadKey)>.head with msgs.take(200) when the thread is
        longer than 200.
    backfillHeads() writes missing .head files for archives imported by older
    builds; it runs once in the background after restore.

6.5 MediaResolver.kt
    - mimeFor(uri): extension -> MIME from a deny-by-default allowlist. No
      text/html, no image/svg+xml (script-capable).
    - sniffMime(file): reads up to 32 bytes and detects png/jpeg/gif/webp/bmp,
      wav/mp3/m4a/mp4/mov etc. Cached by path+length+lastModified. This is what
      makes extensionless Instagram media render instead of becoming a chip.
    - resolve(root, uri): the containment path.
        1. reject empty segments, "." "..", absolute paths syntactically
        2. walk EVERY component with symlink checks (a symlinked parent would
           defeat a final-component-only check)
        3. canonicalise and verify it is still inside the canonical root
        4. follow "root is your_instagram_activity" quirk
      Throws MediaException(status). Never returns an outside path.
    - readCapped(root, uri, max)
    - findInbox(root), resolveByBasename(root, threadKey, name)
    - Caches: threadMediaCache (per root+thread basename map) and sniffCache.
      These caches are why opening a chat is fast. Do not bypass them in hot
      loops.

6.6 ArchivePicker.kt (SAF)
    - directPath(uri): maps a tree URI to a real path only when it is a plain
      local file path AND all-files access is granted. Otherwise null.
    - copyToAppStorage(uri, isFolder, destName): copies to
      filesDir/imports/<destName>, recursively for trees, depth cap 32.
    - extractZip(uri, destDir): streaming ZipInputStream first; on the known
      "unexpected end of zlib input stream" failure (data descriptors / ZIP64
      from phone compressors) it retries via ZipFile on a seekable cache copy.
    - Hardening: backslash member names rejected, absolute/`..` members
      rejected, canonical containment re-check, MAX_ZIP_FILES = 2,000,000,
      MAX_ZIP_UNCOMPRESSED = 8 GiB, 64 KiB copy buffer (never buffers a member).
    - Progress is reported at most every 4 MiB (PROGRESS_STEP).

6.7 MediaSaver.kt
    - download(context, treeUri, source): writes into the user-picked SAF tree,
      creating a unique "name (2)" instead of overwriting.
    - copyToClipboard(context, source, mime): clears cache/clipboard, copies the
      file there, and exposes it through FileProvider so another app can paste
      real media. The export file is never exposed.
    - FileProviderUri.forFile(...) = getUriForFile(packageName + ".fileprovider")

6.8 Prefs.kt (SharedPreferences "igv_prefs", MODE_PRIVATE)
    Display / perspective
      global_me                     global "who am I"
      thread_me:<chatKey>           per-chat override
    Appearance & behaviour
      theme_id, text_scale, compact_rows, animations, autoplay_videos,
      sfx_enabled,
      anim_screen, anim_theme_fade, anim_press, anim_list_rise,
      anim_cascade, anim_date_tick, anim_flare, anim_jump
    Import / storage
      export_path                   legacy single root
      export_paths                  list of roots that make up the archive
      imported_roots                every root ever imported (accumulates)
      imported_fingerprints         "name|size|modified" to reject re-imports
      media_roots                   newline-separated extra media folders
      download_tree, download_tree_name
      allfiles_prompt_dismissed
    Per-chat UI state
      gallery_filter:<chatKey>, gallery_tab:<chatKey>
      rename:<chatKey>\u0000<rawName>            -> display name
      contact_avatar:<chatKey>\u0000<rawName>    -> absolute app-private path
    Notes
      notes                         JSON array (see NoteStore)
    Notes on design:
      - Renames/avatars are keyed by RAW export name, not display name. A rename
        or perspective flip must never move someone's photo.
      - contactAvatar() deliberately does NOT stat the file: it is called once
        per participant per chat at boot. A stale path self-heals (decode fails,
        initial is drawn).
      - Import ADDS to imported_roots; importing a second export keeps the first.
        Delete-index clears all of it.

6.9 NoteStore.kt
    Note(archiveKey, threadKey, msgIndex, text, updatedAt), id = "a|t|i".
    archiveKey is the import root's folder name (see MainActivity).
    Stored in prefs as hand-rolled JSON, because org.json is a throwing stub in
    local JVM tests. encode/decode are pure Kotlin and unit-tested.
    API: all(prefs), save(prefs, note), delete(prefs, archive, thread, idx),
         forMessage(prefs, archive, thread, idx), forgetArchive(prefs, archive).
    A note is anchored to the kept-message INDEX, so deleting/re-importing an
    archive invalidates notes -- which is why Delete-index calls forgetArchive.

6.10 MediaInfo.kt
    MediaMetadataRetriever wrapper: durationMs(path) cached (NONE = unreadable),
    poster(path, maxPx) in a 16 MiB LruCache of downscaled bitmaps,
    formatDuration(ms) -> "1:23" / "1:02:03".

6.11 ImportProgress.kt
    ImportProgress(phase [COPYING, EXTRACTING, INDEXING], fraction?, doneBytes,
    totalBytes, doneItems, totalItems) + formatBytes().

6.12 Text.kt
    Text.fix(s): Instagram stores UTF-8 bytes misdecoded as Latin-1, producing
    mojibake. The repair converts each char to a byte only if every char <= 0xFF,
    then strict-UTF-8 decodes; on any failure it returns the original string.
    Conservative by design. Never apply it to dedupe keys or media URIs.

 7. UI LAYER REFERENCE
================================================================================

7.1 MainActivity.kt -- the composition root
    Activity owns:
      picker, prefs
      pendingUri / pendingUris / pendingFolders / pendingIsFolder
      indexState:   MutableState<ArchiveIndex?>
      importStatus: MutableState<String?>
      importProgress: MutableState<ImportProgress?>
      snapshotFile = filesDir/imports/index.snapshot
      avatarVersion: MutableIntState (bumped when a photo is stored)

    ActivityResult launchers:
      pickZip          OpenMultipleDocuments -> pendingUris (zips)
      pickDir          OpenDocumentTree      -> pendingFolders (export folder)
      pickDownloadDir  OpenDocumentTree      -> persists download tree + name
      pickMediaFolder  OpenDocumentTree      -> adds an extra media root
      pickAvatar       OpenDocument         -> stores a copied avatar

    runImport(onDone):
      1. fingerprint everything picked; keep only not-seen items
         (name|size|modified). All duplicates -> "Already imported", no work.
      2. folder: directPath when all-files access, else copyToAppStorage.
         zip: extractZip into filesDir/imports/export/import-<slug>.
      3. allRoots = (importedRoots + newPaths).distinct(); save prefs.
      4. ArchiveIndex.indexAll(allRoots, prefs.mediaRoots) with progress.
         The result is written to the snapshot if it has threads.
      5. Empty archive: status explains the expected path and skip reasons.
      6. Success: Toast with chat count + skipped count, saveExportPaths.
    Nothing is written into the user's export at any point.

    onCreate:
      Reads the snapshot SYNCHRONOUSLY if it exists and is <= 512 KiB
      (SYNC_SNAPSHOT_MAX_BYTES; a few KB in practice), so the app opens straight
      onto the chat list with no splash.
      Larger/missing snapshots fall through to AppRoot's async restore.

    AppRoot (the big @Composable):
      Owns navigation, selectedKey, targetMsgIndex, chatMessages, perspective
      state, choosers, restore/opening state, and the whole screen switch.

      chats = remember(index, renamesVersion, avatarVersion) { UiMapping.chatItems(
          renameOf, avatarOf (never your own photo), selfOf ) }
      selfOf uses quickSelf, NOT detectMe, because detectMe deserialises a whole
      thread and the chat list asks for every chat at once.

      Chat mapping (LaunchedEffect(index, selectedKey, chatSelf, avatarVersion)):
        - load messages on Dispatchers.IO
        - if <= 250 messages: map everything in one go
        - else: first 250 (FIRST_CHUNK), publish, yield, then 400 at a time
          (CHUNK), and publish the COMPLETE list exactly once at the end.
        - Deliberately NOT keyed on renamesVersion: a rename only changes display
          strings and must not re-map/re-render the entire chat.

      Restore (LaunchedEffect(Unit)):
        - snapshot fast path, else rebuild from savedExportPaths and save a new
          snapshot, else forget the saved roots and say so.
        - backfills .head files after a successful restore.
        - "Opening your archive..." overlay while restoring.

      Back: BackHandler(enabled = nav.canGoBack) -> nav.back()
      Screen switch: AnimatedContent(targetState = nav.current, veil(...))

    Screen wiring (same order as the when block):
      IMPORT   ImportScreen(...)                 also runs autoImport from Settings
      LIST     ChatListScreen(chats, click -> select + navigate CHAT)
      CHAT     ChatScreen(chatName from the mapped list, chatMessages, ...)
      SEARCH   SearchScreen(search = UiMapping.search, notes = NoteStore-derived
               NoteResult list, result click -> select + targetMsgIndex + CHAT)
      SETTINGS SettingsScreen(...)               imports hand off to IMPORT so the
                                                 progress rail is visible
    Global overlays: WhoAmIDialog (global + per chat), Lightbox placeholder,
    first-run all-files prompt.

 8. PERSISTENCE MAP (exact locations)
================================================================================

All paths are app-private; nothing is in the user's export folder.

  filesDir/imports/index.snapshot          Persisted manifest (Serializable)
  filesDir/imports/threads/<sha256(key)>   List<KeptMessage> per thread
  filesDir/imports/threads/<sha256>.head   first 200 messages (fast open)
  filesDir/imports/export/import-<slug>/   extracted zips
  filesDir/imports/<destName>/             copied SAF trees
  filesDir/avatars/<sha256(raw).take(24)>.<ext>   contact photos
  filesDir/avatar.<ext>                    your default photo
  cacheDir/clipboard/<name>                staged clipboard copy (cleared each use)
  SharedPreferences "igv_prefs"            all settings/overrides/notes

Lifecycle:
  - Import ADDS roots; it does not delete the previous archive.
  - "Delete imported data" (MainActivity.deleteIndex) sets indexState = null,
    clears savedExportPaths / savedExportPath / importedRoots /
    importedFingerprints, and deletes filesDir/imports recursively. That removes
    the snapshot, all per-thread files AND every copied/extracted export in app
    storage. The user's original export is untouched.
  - AppRoot additionally calls NoteStore.forgetArchive for the current archive
    before deleteIndex, so notes for that archive are dropped.
  - Avatar files under filesDir/avatars and their prefs entries are NOT removed
    by deleteIndex, despite the confirmation dialog saying "photos". Treat that
    as a known mismatch if you touch deletion.
  - Snapshot is rewritten after every successful import (and after adding a
    media folder, which re-indexes).
  - A snapshot that cannot be read is ignored and rebuilt from saved roots.


================================================================================
 9. THREADING AND PERFORMANCE CONTRACT
================================================================================

  - Disk I/O and indexing: Dispatchers.IO
  - Mapping (UiMapping) and in-chat search scans: Dispatchers.Default
  - Compose state is only assigned on the main thread (LaunchedEffect /
    lifecycleScope with withContext(Main) where needed).
  - Never call ArchiveIndex.detectMe / messages() from a chat-list row or from
    composition: that deserialises threads. Use quickSelf and ThreadSummary.
  - Media resolution dominates mapping cost. Keep ArchiveIndex.mediaFile's order
    (thread basename cache -> roots -> mediaRoots) and do not add per-message
    directory scans.
  - Formatters are hoisted: SimpleDateFormat is constructed once per mapping
    pass, java.time formatters are static, because per-row construction was
    measurable at boot.
  - Chat open is progressive and intentionally publishes only twice: once at
    250 messages, once when everything is ready. Publishing on every chunk made
    per-chat effects re-run and looked like an endless reload.
  - LazyColumn identity is msgIndex; adding/removing list items must not change
    existing indices. If a feature filters messages, do NOT renumber msgIndex --
    it is also the note key.
  - Bitmap work: ThumbDiskCache + MediaInfo.posters (16 MiB LruCache). Avoid
    decoding full-size images per recomposition.
  - Prefs lookups are cheap but not free; avatar/rename lookups are called per
    participant per chat at boot, which is why contactAvatar does not stat files.

 11. INVARIANTS AND TRAPS (reviewer checklist)
================================================================================

  1. No INTERNET permission; no network calls anywhere.
  2. No write to the picked export. Only filesDir/cacheDir/SAF download tree.
  3. Media paths only via MediaResolver/ArchiveIndex.mediaFile.
  4. Message text only via Compose Text/AnnotatedString; links only http(s).
  5. Dedupe key: ts, raw sender, raw content, ordered media URIs; reactions and
     share excluded; sticker is a single object.
  6. Order: ts ASC, seq DESC; seq assigned before dedupe for every raw message.
  7. Within one file, identical messages are all kept; dedupe only against
     lower-numbered files.
  8. Text.fix applies to display text only, never to keys or media URIs.
  9. msgIndex is absolute and stable: it is both the LazyColumn key and the
     note identity. Never renumber it.
 10. rawSender is the identity for renames/photos/perspective; `sender` is
     display-only.
 11. Chat list rows use quickSelf/ThreadSummary, never messages()/detectMe().
 12. Media kind order in Ingest.MEDIA_KINDS must not change (dedupe + UI).
 13. Zip import: reject backslashes, absolute paths, `..`, symlinks; enforce
     file-count and uncompressed-size caps; stream, never buffer a member.
 14. FileProvider exposes ONLY cache/clipboard. Do not add export paths to
     file_paths.xml.
 15. Persisted Serializable classes: `Persisted` has an explicit
     serialVersionUID = 1L, but KeptMessage / MediaRef / ThreadSummary do not.
     Any field change to those silently invalidates every per-thread snapshot
     file (loadThread returns null, so chats open blank) even though the
     manifest still loads. Add explicit serialVersionUID before changing them,
     or invalidate the snapshot and rebuild. Keep proguard -keepnames.
 16. Snapshot/serialization changes require bumping nothing by default, but
     verify an old snapshot still loads or fails gracefully to a rebuild.
 17. Do not commit local.properties, build/ or any real export.
 18. Do not bump versionName without versionCode.
 19. Keep the debug signing config unless you deliberately accept that users
     must uninstall to upgrade.
 20. Lint is disabled for release because of the JDK 25 version-string bug; do
     not silently remove the flag without verifying lint runs.

 14. KNOWN LIMITATIONS / STALE THINGS / GOTCHAS
================================================================================

  - HANDOFF.md and README.md are stale (see the top of this file).
  - A stale comment above `pendingFolders` in MainActivity claims an import
    replaces the previous export. The code does the opposite: runImport ADDS to
    prefs.importedRoots and re-indexes every root. Trust the code.
  - app/build.gradle.kts still carries a comment "The Rust core ships as a JNI
    library per ABI" above `packaging { jniLibs }`. There is no Rust core; the
    packaging block is harmless.
  - Lightbox in MainActivity is a placeholder ("Full-size image"); real viewing
    uses ChatScreen's ImageOverlay. Do not confuse them.
  - Global search is an in-memory full scan (200-hit cap, min 2 chars, text
    only). For very large archives this is linear; there is no FTS index.
  - Notes are anchored to message indices. Re-importing an archive invalidates
    them, which is why Delete-index forgets them. There is no migration.
  - Snapshot serialization is Java-serialization based. `Persisted` is
    version-tolerant (serialVersionUID = 1L), but KeptMessage/MediaRef/
    ThreadSummary have no explicit UID, so a field change makes old thread files
    unreadable while the manifest still loads -- chats then open blank until a
    rebuild/re-import. See section 4.5.
  - Multi-export keys are namespaced only on genuine collisions
    ("<rootSlug>\u00b7<key>"). Per-chat prefs written before a collision import
    will not follow the renamed key.
  - The "who am I" list is built from distinct senders/participants actually
    present in the thread; someone who never posted may not appear.
  - Media resolution covers photos, gifs, stickers, audio_files, videos; other
    kinds (`files`) render as an attachment chip. Extensionless files rely on
    byte sniffing.
  - The app copies a picked folder unless all-files access is granted. A revoked
    grant after an in-place import makes the saved root unreadable; restore then
    forgets it and asks for a re-import.
  - Sound effects are bundled (res/raw/sfx_tap); regenerate with
    tools/gen_sfx.py if the asset ever needs changing.
  - No instrumentation coverage: UI regressions are not caught by the test suite.
  - Photo paging in the full-screen viewer covers the photos of the messages that
    are currently loaded (first 250, then 400 per chunk), the same set the
    library is built from. Older photos appear once their messages load.
